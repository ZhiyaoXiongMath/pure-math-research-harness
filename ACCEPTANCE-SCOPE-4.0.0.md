# PMRS 4.0.0 acceptance scope

The 4.0.0 release scope explicitly replaces the earlier compatibility requirement. This is a product-scope change authorized for this major release, not a waiver of still-applicable tests.

## Retired requirements

- Historical source trees, old runtime invocation, one-way project upgrades, old-format readers and adapters.
- Imported historical proof authority, import certificates and old-format view projections.
- Concrete research archives, migration fixtures, conversion reports and continuation package production.
- Old preview build jobs, old repository ancestry and frozen compatibility inventories.
- Reusing the previous release's private specification-checker counts, browser records or PASS receipts as evidence for this release.

The machine-readable acceptance inventory records the retired case/assertion and baseline mappings with reasons. Removed tests that also exercised native archive, capture recovery, source integrity or security are split: applicable behavior remains tested with minimal generated data. Mathematical witness compatibility is a current scientific concept and is not a retired software compatibility layer.

## Retained required behavior

- Strict knowledge contracts, exact source/body identity, scientific admission, independent scoped assurance, revisions, withdrawal and immutable history.
- TRW/TFDW, all registered stages/paths and reasoning policies, explicit candidate adoption and paused handoffs.
- Budgets, frozen requests, capture admission, UNKNOWN reconciliation, pause/resume controls and no automatic paid dispatch.
- Durable operation identity, lost-response recovery, real desktop restart/port changes and deliberate new operations.
- Native backup/restore to a new paused project, safe archives and clear unsupported-input refusal.
- Session, origin and CSRF protection; static resources; task polling; project/instance/stage navigation.
- Report generation and semantic/visual gates, isolated PDF rendering, settings, offline installation and independent 4.0 default paths.
- Complete current test/resource inventory, exact evidence hashes, package metadata, deterministic builds, fresh repository history and artifact content inspection.

## Evidence boundaries

Acceptance runs on Ubuntu 26.04 using independent temporary workspaces and controlled simulation, without paid research calls. Native GUI actions, installed browser actions, command-line installation, source tests and artifact inspection are recorded separately. A missing native desktop click is reported as unverified rather than inferred from a package check; previous human observations are historical only. Final measured counts and any unverified scope appear in the test report.
