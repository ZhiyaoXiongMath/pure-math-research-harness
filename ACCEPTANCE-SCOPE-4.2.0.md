# PMRS 4.2.0 acceptance scope

This file states Version 4.2.0 requirements without requiring older release documents. The [implementation notes](IMPLEMENTATION-NOTES-4.2.0.md) distinguish repairs to scientific responsibilities and execution from the new project assistant. The [validation record](TEST-REPORT-4.2.0.md) identifies actual development runs, bounded reuse and release-specific checks; a version change does not turn earlier evidence into a new full-suite PASS.

The published v4.1.0 baseline extends the native 4.0 product with SURVEY and English/Simplified Chinese interfaces. It retained TRW/TFDW scientific semantics, model policies, budgets, concurrency, recovery and report rules. Version 4.2.0's concurrency changes are specified separately below. Product versions do not rename historical workflow contracts or native storage identifiers.

## Retained workflow and bilingual-interface requirements

- Native paused SURVEY creation from a new topic, selected existing knowledge or an update; zero model calls at creation.
- Knowledge-only completion without implicit reports; independently selectable minimal, thematic and lecture English manuscripts.
- Bounded real-provider host retrieval, deterministic test provider, actual material versions, reading locations, explicit errors and metadata/full-text distinctions.
- Shared native mathematical knowledge, exact readiness and dependency closure, scoped invalidation, evidence and original/extracted-byte separation.
- Explicit activity authorization, complete stage/role policies, independent review tasks, capture recovery and UNKNOWN accounting.
- Linked paused handoff instances preserving statements, context and sources without granting proof qualification.
- English default, persisted Simplified Chinese preference, complete display resources, English content constraints, and preserved drafts/navigation/scroll while changing language.
- S0–S7 plus preserved P0–P14 and D0–D5, correct current-instance activity, structural previews, polling and stage/tab clearing.
- Packaged translations, diagrams, examples, templates, complete English/Chinese README and consistent source/wheel/release/Debian version metadata.

## Retained gates

Native scientific admission, immutable sources and history, scoped assurance and withdrawal, request freezing, budgets, pause/resume, operation identity, real restart/port recovery, native backup/restore, session/origin/CSRF protection and isolated PDF rendering remain required. New tests supplement these requirements rather than replacing them.

Retained requirements also include consumer-specific mathematical qualification, complete checked/unchecked boundaries, all registered stages and reasoning policies, deliberate candidate adoption and paused handoffs, read-only inspection without dispatch or repair, and independent author/semantic/actual-page report gates. Native backup, capture recovery, exact source identity and session security remain required even where an old test was removed: those behaviors must have current native fixtures and explicit mappings. Mathematical witness compatibility is a current scientific concept, not a retired software compatibility adapter. Complete test/resource inventories, evidence hashes, deterministic builds and package-content verification remain delivery requirements; dependency inspection alone is not a render result.

## Retired software compatibility scope

Earlier-runtime invocation, project upgrade writers, old-format readers/adapters, imported proof authority and import certificates, concrete research archives, migration fixtures and research continuation packages remain outside this product. Historical preview jobs and frozen compatibility inventories do not qualify this version. Old release counts and private PASS receipts are not automatically imported as current evidence. Still-applicable native archive, recovery, source-integrity, scientific and security checks remain required with generated data. No real research project is a development fixture.

The [historical v4.0.0 scope](https://github.com/ZhiyaoXiongMath/Pure-Math-Research-Studio/blob/v4.0.0/ACCEPTANCE-SCOPE-4.0.0.md) records the original retirement decision for provenance only. The current rules above are self-contained. Existing commits, v4.0.0/v4.1.0 tags, Releases and installation assets remain available under their historical identities; removing old documents from the current tree does not change them. A fresh parentless history was a historical 4.0 release action, not a requirement to reset this repository again.

## Version 4.2.0 requirements

- Necessary TRW prerequisites are checked and reused or automatically assigned from the ordinary start entry. Actual dependencies and concrete gaps drive bounded continuation and honest delivery; no implicit next round, human decision or formal report.
- P7 preserves multiple framework-transfer and independent direct-analysis branches, cumulative attempt limits and a shared finite allowance. P8 performs the required targeted work; P11 assesses the global gap. TFDW candidate selection and Survey Knowledge only retain their human and delivery boundaries.
- Project calls may run up to eight within the shared host pool of ten, preserving explicit lower project limits, fair demand-based queues and original budgets. Preparation leases, selected context, immutable material references, checkpoint/cache retention and resource/capture recovery retain measured boundaries without new OS memory or swap limits.
- Project assistant uses its own gpt-6-astra/xhigh purpose and finite allowance, shares the native executor/ledger/pool, diagnoses only relevant native evidence, and executes only explicitly scoped report revisions. Exact old manuscript, cumulative effective requirements, separate finite report authorization, old versions and independent checks are required; paused research stays paused and UNKNOWN is not resent.
- English/Chinese README, the built-in Guide and contextual controls describe the implemented behavior. Source and installer documentation sets are intentional; local document links resolve within each artifact, and source-only test paths are identified as belonging to the matching source ZIP.

The finite T1–T12/workflow-start and A1–A10 project-assistant checks use temporary synthetic projects and controlled responses. Their original source identities and outcomes remain recorded. Unaffected earlier results require a bounded dependency comparison for reuse; versioned menus, package metadata, current documentation and artifact contents receive checks for their actual changed surface. This release preparation does not claim a fresh run of the historical full suite, N03 or every registered browser path. Final build and publication receipts must identify the actual 4.2.0 commit, tree, package metadata and artifact bytes.

## Evidence boundaries

The target is Ubuntu 26.04. Development uses independent workspaces and controlled simulation, with no paid research calls. Synthetic tasks prove software behavior only; they do not establish mathematical review or a real literature investigation. Actual public-provider fetches, compiler/PDF output, installed browser observations and native desktop clicks are recorded separately.

Previous human observations may be reused only when traceable and unaffected. Published 4.1.0 native text and versioned menu changes received targeted human acceptance for installation/menu launch and Tectonic chooser cancellation, separately recorded in the baseline report. A version change that affects native labels or menu entries must identify those changed surfaces separately; earlier native clicks are not renamed as 4.2.0 clicks. Unchanged behavior may reuse traceable implementation evidence, while affected observations and any remaining limits are recorded explicitly. Command-line installation, mocked dialogs and browser automation do not stand in for a human native click. Missing or partial evidence stays visible rather than making a strict gate complete.
