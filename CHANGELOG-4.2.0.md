# PMRS 4.2.0 changes

Version 4.2.0 combines the completed workflow/resource repairs with the new project assistant. The version number identifies this product; it does not rename native storage formats, frozen workflow contracts or earlier request identities. Published v4.1.0 remains available under its original identity.

## Scientific responsibilities and workflow repairs

- Completed actionable input, scientific-work and result duties across the existing 29 stages. P1–P3 check and reuse applicable prerequisites; P7 supports multiple framework-transfer and independent direct-analysis branches; P8 performs targeted work and P11 accounts for the global gap.
- Repaired ordinary-start continuation so actual results, concrete gaps and dependencies drive necessary work within one finite authorization. Deterministic round delivery preserves results, failures, unfinished work and human decisions; formal reports remain explicit requests.
- Added executable corrections in the original round and explicit finite call extensions without restarting unsent old work, losing captures or resetting cumulative responsibility attempts. TFDW candidate adoption and Survey handoffs still create paused instances requiring separate authorization.

## Execution and input repairs

- Shared Web/CLI, research, report and assistant execution supports a saved project limit up to eight within a demand-based host pool of ten, retaining lower project settings, finite budgets and independent-review boundaries.
- Selected-input closures and immutable material references avoid repeated full-body/base64 packet copies. Honest input/output-reserve accounting, bounded streaming, phase-specific preparation/resource admission and exact capture/report continuation retain declared storage and context boundaries.
- Resource waits and accepted-body rendering resume under the original identity; UNKNOWN is not automatically resent. Cleanup preserves original sources, captures, receipts and report evidence.

## New project assistant and exact report revision

- Added one persistent gpt-6-astra/xhigh panel with project, task-issue and exact-report entry points, native-evidence diagnosis, history and bounded diagnostic summaries.
- Added explicit finite assistant allowance, separate report allowance and original-turn recovery through the existing executor, ledger and shared pool. Questions do not resume research or authorize report changes.
- Report revisions read the exact old manuscript and accumulated effective requirements, preserve unselected top-level section bytes, and retain old versions. Full-document scope must be explicit. Revised content receives fresh semantic requirements checks, actual rendering and all-page review; paused research remains paused.

## Documentation and distribution

- Expanded the English/Chinese README and in-app Guide with ordinary-start instructions, three complete workflow examples, six inline diagrams, correction and recovery steps, assistant usage and exact limitations.
- Updated product, menu, installer and distribution identities to 4.2.0 while preserving native data-format identifiers and the existing 4.x data locations. Older release documents remain available in Git history; removed 4.0 documents are not restored in this tree.
- Validation distinguishes finite development executions, recorded reuse of unaffected behavior, this version's artifact checks and the historical v4.1.0 baseline. See [validation](TEST-REPORT-4.2.0.md), [scope](ACCEPTANCE-SCOPE-4.2.0.md), [implementation notes](IMPLEMENTATION-NOTES-4.2.0.md) and [installation](UBUNTU-E2E-GUIDE.md). - Added native SURVEY S0–S7 for scoped literature investigation, reading, shared knowledge organization, independent readiness checks, frozen writing plans and reviewed delivery.
