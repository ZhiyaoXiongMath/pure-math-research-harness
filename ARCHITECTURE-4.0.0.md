# PMRS 4.0.0 architecture

The application exposes one native mathematical research runtime through shared Engine and Workspace services. The browser and CLI do not implement independent research semantics.

## Knowledge and authority

Strict records have six kinds: Context, Statement, Argument, Example, SourceEvidence and Assessment. Content identities, logical revisions, immutable body/source locators, production events, scoped support, consumer-specific qualification and withdrawal remain separate. Native scientific admission uses the same validation for preflight, live execution and capture recovery. Saving an object never grants proof authority. Context closures preserve complete source bytes and checked/unchecked boundaries.

## Work and history

TRW and TFDW own independent instances, missions, authorizations, budgets, obligations and attempts. The registered stage/role/purpose policy freezes requested model settings before dispatch. Captured results retain their original request identity; uncertain requests are not automatically resent or refunded. Native project history is the immutable commit/event journal, with report revision history kept separately. Prior task history is not erased by a new round.

## Storage and services

The journal uses content-addressed blobs, sparse deltas and reference checkpoints. SQL is a disposable projection; reads do not repair, dispatch or resume work. The storage format identifier remains independent of product version. Current native archives retain the journal and objects; restore validates them into a new destination and pauses workflows. Unsupported shapes or removed import-only data fail explicitly. There are no old-format readers, upgrade writers or historical runtime fallback.

Each desktop workspace has a loopback service, session/origin/CSRF protection, a stable workspace identity and durable idempotent operation receipts. Unacknowledged results can be discovered across service restarts or port changes without resubmitting a form. 4.0 defaults use isolated workspace/configuration locations and browser storage namespaces. Installation uses separate menu and Debian package identities.

## Reports and surface

Report authoring, semantic review, actual-page review and rendering are separate from scientific knowledge. Reports do not create proof support. Rendering confines compiler input and preserves failures. Dependency inspection is not a render result. Workflow diagrams retain every registered stage and path, but show the selected main path by default with scoped activity and details. Lightweight polling updates tasks without replacing a reader's mathematical body.

## Validation and distribution

Fresh native tests, synthetic project fixtures, installed browser observations and artifact inspections qualify this version. Removed compatibility requirements are explicitly retired in the acceptance registry. Native backup/recovery and all applicable mathematical, execution and security checks remain required. No old test result is imported as current evidence. Release artifacts contain this product only; private test outputs and research data stay outside the repository.
